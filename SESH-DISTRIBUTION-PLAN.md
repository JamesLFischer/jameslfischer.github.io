# SESH distribution plan (draft, nothing published)

## 1. Windows export
- Godot 4.3 export templates (`Godot_v4.3-stable_export_templates.tpz`) on the box; add `export_presets.cfg` with a "Windows Desktop" preset (x86_64, embed PCK off so the .pck can be replaced alone).
- Ship maps (GLBs) and assets in the zip next to the exe, since the hub loads GLBs at runtime from the play folder.
- Build: `godot --headless --path desktop --export-release "Windows Desktop" build/SESH.exe`, then zip `SESH.exe`, `SESH.pck`, maps and `assets/` into `SESH-<version>.zip`.

## 2. Update manifest
Hosted at `https://jameslfischer.github.io/sesh/sesh-manifest.json`, generated by `sesh_world/play/desktop/make_manifest.py`:
```json
{ "name": "SESH", "version": "0.2.0", "released": "2026-11-02T03:00:00+00:00", "notes": "",
  "windows": { "file": "SESH-0.2.0.zip",
               "url": "https://github.com/JamesLFischer/sesh/releases/download/v0.2.0/SESH-0.2.0.zip",
               "sha256": "<64 hex>", "size": 123456789, "sig_ed25519": "<optional hex>" } }
```
- SHA-256 + size are checked before anything is used. A wrong hash deletes the download.
- Optional ed25519: `make_manifest.py --key` signs the canonical `windows` object. The launcher would hold the public key. This protects against a tampered manifest, not just a corrupted download. Godot 4.3 has no built-in ed25519 verify, so it needs a GDExtension or a small helper exe; v1 can ship SHA-256 only (manifest is served over HTTPS from James's own repo).

## 3. Launcher flow (`desktop/updater.gd`, prototype)
1. On hub start: `apply_pending()`; if a verified zip is staged, a small bootstrapper (`SESH-Updater.exe` or `.bat`) extracts it over the install and relaunches. A running exe on Windows can't overwrite itself, so the swap happens outside the game process.
2. `check(url)`: fetch manifest, compare semver with `user://installed_version.txt`.
3. Newer: download to `user://update_stage/`, verify SHA-256 + size, write `pending.json`.
4. Tell the player "Update ready, restart to apply." Network failure or bad hash: keep playing the current version.
- Keep the previous install folder (`SESH/previous/`) for rollback if the new one fails to start.
- Tested headless on the box (Godot 4.3, local HTTP): good manifest -> "verified and staged"; wrong hash -> "hash mismatch, update discarded". Not wired into hub.gd yet.

## 4. Hosting
- GitHub Pages: 100 MB per-file limit, ~1 GB site size, soft 100 GB/month bandwidth. Fine for the manifest and a download page, not for the game zip (Woods GLBs alone are ~5 MB each, many versions, so zips will grow).
- Recommendation: manifest + download page on jameslfischer.github.io, binaries as GitHub Releases assets (2 GB per file, no stated bandwidth cap) on a separate repo, e.g. `JamesLFischer/sesh`.
- Ship only the newest map version per environment in the release, not every v0xx.

## 5. SmartScreen
- An unsigned exe shows "Windows protected your PC" until it builds reputation. Friends need "More info -> Run anyway". Say so on the download page.
- Fix later: code-signing certificate (OV ~$200-400/yr, still builds reputation; EV removes the warning faster) or Azure Trusted Signing (~$10/mo, needs identity verification).
